# Microgame: DuckDuck

## Concept
The player is a duck in a field, and there are hunters trying to shoot them down.

## Player Action
Using swipe gestures, the player must direct the bird away from where the hunters are aiming until they run out of ammunition.

## Success / Failure
**Success condition:**  The player stays alive until the "Hunters Remaining" reaches 0.

**Failure condition:**  The player gets caught and shot in a hunter target zone.

## Programming Focuses
This microgame **primarily** demonstrates:

This microgame specifically and additionally demonstrates:

## How the Programming Works
[GameController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\GameController.cs) inherits [MicrogameBehaviour.cs](MobileGameProject\Assets\Scripts\Framework\MicrogameBehaviour.cs). It is attached to the GameManager object in [MG1_DuckDuck.unity](MobileGameProject\Assets\Scenes\MG1_DuckDuck.unity) to handle game management per the [framework](Documentation\Framework.md), as well as:
- Declares a `SpawnHunter()` function to instantiate `GameObject hunterPrefab`, declared as a variable, at a random position in the game.
- If `IsRunning == true`, run a declared `private void HunterSpawnCycle()` function every frame which runs and resets a timer to repeat `SpawnHunter()`.
- Declares a `SetHunterRemainingText()` to update the game's UI when a hunter tries to shoot the player, referred to by [HunterController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\HunterController.cs).
- Holds a `hunterCount` variable to track how many hunters are left. When it reaches 0 and the player is not hit per a boolean `IsPlayerHit` variable, it calls the framework's `Win()`. Otherwise, if the player does get hit, it calls `Lose()`.

[HunterController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\HunterController.cs) inherits MonoBehaviour and does the following:
- Holds [GameController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\GameController.cs) in a `GameController` variable, and assigns it at `Start()` via `GameObject.Find().GetComponent<>()`.
- Declares a `SetTimer(float time)` function to begin the "lifetime" of the hunter object the script is attached to. In `Start()`, a declared `shotTime` variable is passed into the function.
- Declares a `SetRandomSize(float minSize, float maxSize)` to randomise the size of each hunter target zone instantiated.
- Declares a `RunTimer()` function which runs every `Update()` to decrease the remaining "lifetime" of the hunter object by `Time.deltaTime`. When the "lifetime" reaches the end, `Shoot()` is called.
- Declares a `Shoot()` function which reduces the `hunterCount` and calls `SetHunterRemainingText()` in [GameController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\GameController.cs), checks whether the player is seen via a boolean `IsPlayerSeen` variable in [GameController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\GameController.cs), then sets `IsPlayerHit` accordingly and destroys the hunter object.
- Uses `OnTriggerEnter2D()` and `OnTriggerExit2D()` to detect the player and set `IsPlayerSeen` accordingly.

[PlayerController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\PlayerController.cs) inherits MonoBehaviour and does the following:
- Holds [GameController.cs](MobileGameProject\Assets\Scripts\Microgames\MG1_DuckDuck\GameController.cs) in a `GameController` variable.
- Holds `Input Action` variables to use the Unity Input System for keyboard control. For mobile touchscreen input, `Vector2` variables are held to calculate swipe input.
- Holds `Rigidbody2D`, `int`, and `float` variables for player movement physics and speed.
- In `Awake()`, the `Input Action` variables are assigned to input bindings from the Unity Input System.
- Declares a `SwipeInputHandler()` function to detect and calculate swipe gestures and direction from the player. It assigns values to variables which are then referred to by `DartPlayer()`.
- Declares a `RandomisePlayerVelocity()` function to get a random value for the player's X and Y velocity, to later be applied to the player's rigidbody.
- Declares a `SetPlayerSpeed()` function which applies the values set by `RandomisePlayerVelocity()` to the actual rigidbody.
- Declares a `DartPlayer()` function to check for pressed/swiped inputs, and depending on the input, the X/Y velocity of the player's rigidbody is amended.
- In `Start()`, the player's rigidbody component is assigned to the declared variable, and both `maximumPlayerSpeed` and `playerDartForce` are set. Then two functions, `RandomisePlayerVelocity()` and `SetPlayerSpeed()` are called.
- In `Update()`, `SetPlayerSpeed()`, `SwipeInputHandler()`, and `DartPlayer()` are called every frame.
- An `OnCollisionEnter2D()` function is declared to detect whenever the player hits the sides of the play area. Depending on which side of the play area is hit, some of the player's rigidbody velocities are inverted to create a "bounce off" effect.
